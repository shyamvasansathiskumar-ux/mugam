    01 · The problem

    You can change a password. Not your face.

    Most face logins send a picture or a face template to a server and compare it there. That server becomes the most valuable thing to steal, and a leaked face can't be reset.

    i.

    Leaks are forever

    A stolen password is changed in a minute. A stolen face template is yours for life.

    ii.

    Photos fool cheap checks

    A printed photo or a phone screen held to a webcam passes a lazy face match.

    iii.

    Mugam keeps it home

    The face is checked on the device. The server only ever sees a signature from a key it can't export.

    02 · How it works

    Look, move, match, sign.

    The last card is running for real: this page made a P-256 key in your browser that cannot be exported, and it signs a fresh challenge every few seconds.

    1Look

    The camera frame stays in memory.

    face foundtiny face detector
    points68 landmarks
    template128 numbers

    A face model turns the frame into 128 numbers. The frame itself is dropped. Nothing is drawn to disk or sent anywhere.

    2Move

    Two random moves prove you're there.

    Two of turn left, turn right and blink, in a random order, a few seconds each, one face only. A photo can't follow orders it hasn't seen.

    3Match

    Compare with the template on this device.

    distance0.31
    threshold< 0.50

    Every capture must match. The stored template is rotated by a secret and encrypted with a key the browser won't export.

    4Sign

    Unlock the key. Sign the challenge.

    The challenge is used once, expires in two minutes and is bound to this site's address, so a look-alike site can't replay it.

    03 · Liveness

    A photo can't turn its head.

    Turning is measured from where the nose sits between the eyes. A blink is the eye aspect ratio, from Soukupová and Čech (2016): the eye's height over its width, which drops to almost nothing when the lid closes.

    The face must stay one face, in one place. If a second face appears, or the face jumps across the frame the way a swapped photo does, the scan fails.

    Eye aspect ratio

    EAR = (|p2 − p6| + |p3 − p5|) / (2 · |p1 − p4|)

    EAR now0.30
    counts as a blink below0.21

    End-to-end test: a still photo of the enrolled face, played through a fake camera, never signs in.

    04 · A template you can cancel

    Leak it. Cancel it. Same face, new numbers.

    Mugam never stores the 128 numbers as they come out of the model. It multiplies them by a secret random rotation first. A rotation keeps every distance the same, so matching still works, but the stored numbers look nothing like the original.

    Set your face up again and you get a new rotation. The old template stops matching anything, which is the "renewability" goal of ISO/IEC 24745.

    Eight numbers stand in for 128 here. The rotation is built the same way as in Mugam: a seeded random matrix made orthonormal with Gram–Schmidt.

    05 · What the server keeps

    Nothing worth stealing.

    Public keys only

    Each device's P-256 public key. A copy of the database signs nothing.

    Recovery codes, hashed

    Ten one-time codes, about 60 bits each, stored as PBKDF2 hashes with 210,000 rounds.

    A keyed log

    Every sign-in, failure and new device in an HMAC chain. An edited or cut-off log shows as broken.

    No names in the log

    Events are filed under a keyed pseudonym of the account, so a reused username never sees old history.

    No lockout without a secret

    Failed sign-ins are logged but never lock the owner out. Only wrong recovery codes count.

    A 24-hour hold

    A device added with a recovery code can't remove your other devices for a day. A stolen code can't take over at once.

    07 · What it can't do

    Honest about the edges.

    1. A webcam sees no depth. Face ID uses an infrared dot projector. A skilled deepfake or a good mask could pass liveness, which is why the face only unlocks a key on your own device.
    2. Malware on the device wins. Code inside a compromised browser could use the key without a face. Hardware passkeys are stronger; Mugam suits devices without built-in biometrics.
    3. Face models aren't equally accurate for everyone. The match threshold is stricter than the model's default, and recovery codes mean nobody is locked out by the model.
    4. The Pages demo protects nothing. Its "server" runs in your browser. Run the Java server for the real thing.

    08 · Run it

    Plain Java. No dependencies.

    The server is the JDK's own HTTP server and crypto, nothing else. The face model runs in the browser. Needs JDK 21.

    Before a real deployment

    Put it behind HTTPS, keep the pepper file away from the data folder, and tell it which proxy to trust. SECURITY.md has the full threat model.

    $ bash scripts/test.sh        # 46 Java + 13 Node
$ bash scripts/e2e.sh         # 20 in a real browser
$ bash scripts/serve.sh 8080
Mugam on http://localhost:8080

$ java -cp server/out mugam.Server \
    --origin https://login.example.in \
    --pepper /etc/mugam/pepper \
    --trusted-proxy 10.0.0.2
